## 1. Quantitative Trading Strategies

### 1.1 Strategy Families

| Strategy | Description | Time Horizon | Key Metrics |
|----------|-------------|--------------|-------------|
| Trend Following | Buy strength, sell weakness; exploits momentum persistence | Medium-to-long | Sharpe > 1.5, Calmar > 1.0 |
| Mean Reversion | Buy dips, sell rallies within ranges using RSI, z-scores | Short | High win rate, low drawdown |
| Statistical Arbitrage | Exploit relative mispricings between correlated assets | Short-to-medium | IC > 0.03, ICIR > 0.5 |
| Market Making | Provide liquidity, profit from bid-ask spread | Ultra-short | Fill rate, spread capture |
| High-Frequency Trading | Exploit micro inefficiencies at millisecond scale | Ultra-short | Latency, throughput |
| Pairs Trading | Trade cointegrated pairs, long underperformer, short outperformer | Medium | Correlation > 0.7, half-life < 20 days |
| Momentum Ignition | Detect and ride algorithmic momentum spikes | Ultra-short | Speed, signal-to-noise ratio |

### 1.2 Strategy Design Principles

1. **Clear Hypothesis**: Start with testable economic intuition
2. **Signal Decay**: Monitor alpha decay; typical half-life 2-4 weeks without adaptation
3. **Regime Awareness**: Different strategies excel in different market states
4. **Transaction Cost Awareness**: Include slippage, spread, and impact in backtests
5. **Robustness**: Test across multiple assets, time periods, and market conditions

### 1.3 Key Strategy Formulas

**Moving Average Crossover (Trend Following)**
```
Signal = MA_fast - MA_slow
Entry: Signal > 0 (bullish crossover)
Exit: Signal < 0 (bearish crossover)
```

**RSI Mean Reversion**
```
RSI = 100 - 100 / (1 + RS)
RS = Avg(Gain) / Avg(Loss)
Entry_long: RSI < 30 (oversold)
Entry_short: RSI > 70 (overbought)
```

**Bollinger Band Mean Reversion**
```
Upper Band = MA + k * σ
Lower Band = MA - k * σ
Entry: Price touches lower band (long) or upper band (short)
Exit: Price returns to middle band
```

**Momentum Score**
```
Momentum = (Price_t / Price_{t-n}) - 1
Weight = Momentum / sum(Momentum)  # for ranking
```

| Metric | Minimum | Good | Excellent |

| Sortino Ratio | > 1.5 | > 2.0 | > 3.0 |

## 2. Algorithmic Trading Execution

### 2.1 Order Execution Algorithms

**VWAP (Volume-Weighted Average Price)**
- Executes orders to match volume-weighted average price
- Best for: Large orders, liquid markets
- Formula: `VWAP = Σ(Price_i * Volume_i) / Σ(Volume_i)`

**TWAP (Time-Weighted Average Price)**
- Distributes trades evenly over time
- Best for: Reducing market impact, hiding order size
- Formula: `TWAP = ΣPrice_i / n`

**Implementation Shortfall**
- Minimizes cost between decision price and execution price
- Components: Market impact, spread, timing risk, opportunity cost
- Formula: `IS = (Execution Price - Decision Price) / Decision Price`

**Participation Rate**
- Controls order size as percentage of market volume
- Typical: 5-20% of ADV (Average Daily Volume)
- Formula: `Participation = Order Size / Market Volume`

### 2.2 Market Microstructure

**Bid-Ask Spread Components**
```
Total Spread = Quoted Spread + Effective Spread + Realized Spread
- Quoted Spread: Best bid - Best ask
- Effective Spread: 2 * |Trade Price - Midpoint|
- Realized Spread: 2 * |Trade Price - Midpoint_{5min}|
```

**Market Impact Models**
```
Permanent Impact: I_perm = γ * σ * P * (Q / V_ADV)
Temporary Impact: I_temp = η * σ * P * (v / V_bar)^α
Total Impact = I_perm + I_temp

Parameters:
- γ ≈ 0.314 (permanent impact coefficient)
- η ≈ 0.142 (temporary impact coefficient)
- α ≈ 0.5 (exponent)
```

**Square-Root Law of Market Impact**
```
Impact ∝ √(Order Size / ADV)
```

### 2.3 Execution Quality Metrics

| Metric | Description | Target |
|--------|-------------|--------|
| Slippage | Difference between expected and actual fill price | < 10 bps |
| Market Impact | Price movement caused by order | < 20 bps |
| Timing Risk | Price change between decision and execution | < 5 bps |
| Opportunity Cost | Difference between best execution and actual | < 15 bps |
| Fill Rate | Percentage of order filled | > 95% |
| Implementation Shortfall | Total cost vs arrival price | < 30 bps |

## 3. AI/ML Automation in Trading

### 3.1 AI Pipeline Architecture

```
Data Acquisition → Feature Engineering → Model Training → Signal Generation → Portfolio Construction → Order Execution → Risk Monitoring
```

### 3.2 Machine Learning Models

**Time Series Models**
- LSTM/GRU: Sequential patterns, long-term dependencies
- Transformers: Attention mechanisms for long-range forecasting
- Temporal Fusion Transformers: Multi-horizon forecasting with interpretability

**Tree-Based Models**
- XGBoost/LightGBM: Tabular features, interpretable
- Random Forest: Ensemble robustness
- Gradient Boosting: Sequential error correction

**Deep Learning**
- CNNs: Spatial patterns in limit order books, chart images
- Autoencoders: Dimensionality reduction, anomaly detection
- GNNs: Asset correlation graphs, sector relationships

**Reinforcement Learning**
- PPO (Proximal Policy Optimization): Stable policy gradients
- DQN: Discrete action spaces
- A2C/A3C: Continuous trading actions
- Risk-sensitive RL: CVaR-PPO, risk-adjusted rewards

### 3.3 LLMs in Quantitative Finance

**Primary Roles**
1. **Predictors**: Return forecasting, sentiment extraction
2. **Agents**: Autonomous research, backtesting, execution
3. **Analysts**: Financial statement analysis, earnings call summarization

**Key Applications**
- Sentiment analysis from news, social media, filings
- Factor generation and explanation
- Multi-modal analysis (text + numbers + charts)
- Code generation for strategy implementation
- Risk assessment from unstructured data

**LLM-Driven Frameworks**
- Alpha-GPT: Human-AI interactive factor mining
- R&D-Agent(Q): Automated factor-model co-optimization
- FinRL-DeepSeek: LLM-infused risk-sensitive RL
- FinCon: Multi-agent financial decision making

**Best Practices**
- Retrieval-augmented generation (RAG) for factual accuracy
- Tool-verified numerics before trading decisions
- Timestamped citations for auditability
- Separate signal generation from portfolio allocation
- Time-safe evaluation with document availability checks

### 3.4 Multi-Agent Systems

**Agent Types**
- **Research Agent**: Hypothesis generation, literature review
- **Data Agent**: Feature engineering, data validation
- **Model Agent**: Training, validation, hyperparameter tuning
- **Execution Agent**: Order routing, slippage optimization
- **Risk Agent**: Real-time monitoring, circuit breakers

**Coordination Patterns**
- Hierarchical: Manager agent delegates to specialists
- Debate: Multiple agents argue, arbiter decides
- Pipeline: Sequential processing with handoffs
- Blackboard: Shared workspace for collaboration

### 3.5 Automation Workflow

**Stage 1: Data Collection**
- Millisecond tick data
- Alternative data (sentiment, news, satellite)
- Corporate actions and fundamentals
- Point-in-time data to avoid lookahead bias

**Stage 2: Feature Engineering**
- Technical indicators (RSI, MACD, Bollinger Bands)
- Statistical features (z-scores, rolling moments)
- Alternative data features (sentiment scores, embeddings)
- Regime features (volatility, trend strength)

**Stage 3: Model Training**
- In-sample training (70% of data)
- Cross-validation with purging/embargo
- Hyperparameter optimization
- Model selection based on out-of-sample performance

**Stage 4: Signal Generation**
- Ensemble of multiple models
- Regime-adaptive weighting
- Confidence scoring
- Signal decay adjustment

**Stage 5: Portfolio Construction**
- Risk budgeting
- Position sizing (Kelly, volatility parity)
- Constraint optimization (sector limits, turnover)
- Transaction cost modeling

**Stage 6: Execution**
- Algorithm selection (VWAP, TWAP, IS)
- Smart order routing
- Real-time slippage monitoring
- Post-trade analysis

## 4. Portfolio Management

### 4.1 Portfolio Construction Methods

**Mean-Variance Optimization (Markowitz)**
```
Maximize: μ'w - λ * w'Σw
Subject to: Σw = 1, w ≥ 0
```
- Challenges: Estimation error in Σ, sensitivity to inputs

**Hierarchical Risk Parity (HRP)**
- Uses machine learning clustering on correlation matrix
- Avoids matrix inversion instability
- Recursive bisection for weight allocation

**Risk Parity**
- Equal risk contribution from each asset
- Formula: `w_i ∝ 1 / σ_i`
- Leveraged to target return

**Kelly Criterion**
```
f* = (p * b - (1 - p)) / b
where:
- p = win probability
- b = win/loss ratio
- f* = optimal fraction of capital
```
- Use fractional Kelly (0.25-0.5) to reduce drawdowns
- Quarter-Kelly reduces max drawdown by ~40%

**Equal Volatility Contribution**
```
σ_target = Portfolio target volatility
w_i = σ_target / (N * σ_i)
```

### 4.2 Portfolio Rebalancing

**Rebalancing Triggers**
- Calendar-based: Monthly, quarterly
- Threshold-based: 5-10% drift from target
- Volatility-based: When realized volatility exceeds target

**Transaction Cost Considerations**
- Explicit: commissions, fees, taxes
- Implicit: slippage, market impact, opportunity cost
- Total cost target: < 50 bps per trade

### 4.3 Portfolio Metrics

| Metric | Formula | Target |
|--------|---------|--------|
| Sharpe Ratio | (R_p - R_f) / σ_p | > 1.5 |
| Sortino Ratio | (R_p - R_f) / σ_downside | > 2.0 |
| Calmar Ratio | CAGR / Max Drawdown | > 1.0 |
| Information Ratio | (R_p - R_b) / σ_(p-b) | > 0.5 |
| Alpha | Excess return over benchmark | > 2% annually |
| Beta | Systematic risk | 0.5-1.5 |
| Tracking Error | σ_(p-b) | < 5% annually |

## 5. Regime Detection and Adaptation

### 5.1 Market Regimes

| Regime | Characteristics | Strategy |
|--------|-----------------|----------|
| Low-Vol Trend | ADX > 25, low volatility | Trend following |
| Low-Vol Range | ADX < 20, low volatility | Mean reversion |
| High-Vol Trend | ADX > 25, high volatility | Reduced trend exposure |
| High-Vol Crisis | ADX < 20, high volatility | Cash preservation |

### 5.2 Regime Detection Methods

**Hidden Markov Models (HMM)**
- Gaussian HMM with returns and volatility features
- 3-state model: trending, range-bound, crisis
- Viterbi algorithm for state sequence decoding

**Bayesian Online Changepoint Detection (BOCPD)**
- Real-time changepoint detection
- Hazard function: `P(changepoint at t) = 1 / λ`
- Student-t predictive distribution

**Hurst Exponent**
```
H > 0.55: Trending (persistent)
H < 0.45: Mean-reverting (anti-persistent)
H ≈ 0.50: Random walk
```
- Rescaled range analysis
- Log-log regression of R/S vs lag

**ADX/ATR Filter**
- ADX > 25: Strong trend
- ADX < 20: Weak trend/range
- ATR percentile > 85%: High volatility

### 5.3 Dynamic Strategy Allocation

**Regime-Based Weighting**
```
Weights = f(Regime)
- Low-vol trend: 100% trend, 0% mean reversion
- Low-vol range: 0% trend, 100% mean reversion
- High-vol trend: 75% trend, 25% mean reversion
- High-vol crisis: 0% both, cash preservation
```

**Volatility Targeting**
```
Position Size = Target Vol / Current Vol
where:
- Target Vol = 10-15% annualized
- Current Vol = 20-day realized volatility
```

## 6. Backtesting and Validation

### 6.1 Backtesting Framework

**Data Requirements**
- Point-in-time data (no lookahead bias)
- Survivorship-bias-free universe
- Corporate action adjustments
- Realistic bid-ask spreads and slippage

**Validation Hierarchy**
1. In-sample optimization
2. Out-of-sample testing
3. Walk-forward analysis
4. Paper trading
5. Live deployment (small capital)

### 6.2 Walk-Forward Optimization (WFO)

```
Window Structure:
[IS1 | OOS1 | IS2 | OOS2 | IS3 | OOS3 ...]
  252     63    252    63    252    63

Walk-Forward Efficiency (WFE):
WFE = OOS_Sharpe / IS_Sharpe
Minimum acceptable: WFE > 0.6
```

### 6.3 Cross-Validation Methods

**Purged Cross-Validation**
- Remove observations around train-test boundary
- Purge gap: 1-2x holding period
- Prevents information leakage

**Embargoed Cross-Validation**
- Additional embargo period after test fold
- Typically 1-5% of data length
- Accounts for autocorrelation in financial data

**Combinatorial Purged CV (CPCV)**
- Tests multiple train/test combinations
- More robust than standard k-fold
- Accounts for path dependence

### 6.4 Overfitting Prevention

**Multiple Testing Corrections**
- Deflated Sharpe Ratio (DSR): Adjusts for number of trials
- Bonferroni correction: p_adj = p * n_trials
- False Discovery Rate (FDR): Benjamini-Hochberg procedure

**Monte Carlo Permutation Test**
- Randomize trade order
- Compare actual Sharpe to permutation distribution
- P-value = fraction of permutations with Sharpe >= actual

**Minimum Backtest Length (MinBTL)**
```
MinBTL = (SR_observed / SR_required)^2 * T_required
```

### 6.5 Performance Metrics

| Metric | Formula | Interpretation |
|--------|---------|----------------|
| Sharpe Ratio | √252 * mean(R) / std(R) | Risk-adjusted return |
| Sortino Ratio | √252 * mean(R) / std(R_downside) | Downside risk-adjusted |
| Calmar Ratio | CAGR / MaxDD | Return per unit drawdown |
| Information Ratio | (R_p - R_b) / σ_(p-b) | Active return per tracking error |
| Alpha | α in CAPM regression | Excess return over beta |
| Beta | Cov(R_p, R_b) / Var(R_b) | Systematic exposure |
| Win Rate | #Wins / #Trades | Probability of profit |
| Profit Factor | Gross Profit / Gross Loss | Net profitability |
| Expectancy | (P_win * W) - (P_loss * L) | Average trade expectation |
| R-Multiple | (Exit - Entry) / (Entry - Stop) | Risk-normalized return |

## 7. Data Pipelines and Feature Engineering

### 7.1 Data Sources

**Market Data**
- OHLCV prices (tick, bar, daily)
- Level 2/3 order book data
- Trade and quote data (TAQ)
- Corporate actions (splits, dividends)

**Alternative Data**
- News sentiment (Reuters, Bloomberg, Twitter)
- Earnings call transcripts
- SEC filings (10-K, 10-Q, 8-K)
- Satellite imagery, credit card data
- Web traffic, app downloads

**Macro Data**
- Interest rates, yield curves
- Inflation, GDP, employment
- Commodity prices, FX rates
- Volatility indices (VIX, VXN)

### 7.2 Feature Engineering

**Price-Based Features**
- Returns: simple, log, percentage
- Momentum: 1m, 3m, 6m, 12m
- Volatility: ATR, realized volatility, GARCH
- Technical indicators: RSI, MACD, Bollinger Bands

**Statistical Features**
- Z-scores: (x - μ) / σ
- Rolling moments: mean, std, skewness, kurtosis
- Correlation features: rolling correlation, beta
- Fractional differentiation for stationarity

**Alternative Data Features**
- Sentiment scores: FinBERT, VADER, LLM-based
- Topic embeddings: LDA, BERTopic
- Named entity recognition: companies, people, events
- Event extraction: mergers, earnings, guidance

**Feature Selection**
- Correlation analysis: remove multicollinearity
- SHAP values: feature importance from tree models
- Mutual information: non-linear relationships
- L1 regularization: sparse feature selection

### 7.3 Data Quality

**Cleaning Steps**
- Remove duplicates and outliers
- Fill missing data (forward fill, interpolation)
- Adjust for corporate actions (split-adjusted prices)
- Handle survivorship bias (include delisted assets)

**Point-in-Time Considerations**
- Use data available at time of decision
- Avoid lookahead bias in backtests
- Timestamp all data sources
- Version control for datasets

## 8. Risk Management

### 8.1 Risk Categories

**Market Risk**
- Drawdown limits: max 15% daily, 30% monthly
- VaR/CVaR limits: 1-day VaR < 2% of portfolio
- Concentration limits: max 5% single asset, 25% sector

**Execution Risk**
- Slippage limits: max 20 bps per trade
- Latency monitoring: P99 < 100ms
- System uptime: > 99.9%

**Model Risk**
- Overfitting detection: DSR, permutation tests
- Regime change detection: BOCPD, HMM
- Model drift monitoring: feature distribution shifts

**Operational Risk**
- Kill switches: automatic halt on losses
- Reconciliation: pre-trade, post-trade checks
- Audit logs: all decisions and executions

### 8.2 Position Sizing

**Fixed Fractional**
```
Position Size = Capital * Risk Fraction / (Entry - Stop)
Risk Fraction: typically 0.5-2% per trade
```

**Kelly Criterion**
```
f* = (p * b - (1-p)) / b
Applied: f = f* * kelly_fraction (0.25 = quarter-Kelly)
```

**Volatility Targeting**
```
Position = Target_Vol / Realized_Vol * Notional
Target Vol: 10-15% annualized
```

**Heat Capacity**
```
Total Heat = Σ Risk_i * Correlation_Adjustment
Max Heat: typically 5.0R units
Correlation Penalty: 1.5x for |ρ| > 0.3
```

### 8.3 Circuit Breakers

| Level | Trigger | Action |
|-------|---------|--------|
| Level 1 | Daily loss > 2% | Reduce position size 50% |
| Level 2 | Daily loss > 4% | Close all positions, halt trading |
| Level 3 | Weekly loss > 10% | Full system shutdown, manual review |
| Level 4 | Monthly loss > 20% | Strategy review, parameter reset |
