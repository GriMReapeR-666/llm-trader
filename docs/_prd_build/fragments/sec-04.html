04 04. End-to-End Trading Lifecycle (Start → Finish)

Everything in the system converges into one loop. The outer loop lives in mt5_trader.py main() (~4218+); the inner cycle lives in intelligence/llm_orchestrator.py execute_cycle (~5720). Understanding these two functions is understanding the product.

04.1 The outer pulse loop (one iteration = one "pulse")

  1. Holiday check — orch.data_provider.api_manager.is_holiday(). On a holiday the loop does not exit: it calls orch.pulse_maintenance(...) with a best-effort symbol so reconciliation, health, memory and kill-switch schedules keep running, while analysis is skipped (~4222–4279).
  2. Autonomous research tick — every 10th cycle (cycle_count % 10 == 0) runs operations.autonomous_pipeline.run_pipeline(...) with the lifecycle path, the alert outbox and the task queue. It reports discovered / registered / skipped / flagged counts and sits before the holiday gate so research progresses 24/7 (~4238–4262).
  3. Symbol selection — in AUTO mode MarketScanner.scan(timeframe, limit_to_watchlist) ranks opportunities; results are cached to scanner_state.json for the API/deck (~4280–4300).
  4. Pre-pulse ingest hoisted once — orch.pre_pulse_macro_ingest(current_symbol, paper_mode) runs before the strategy thread pool so calendar/news/FRED ingestion cannot double-ingest and contend on SQLite when two strategies run in parallel (~4446–4451).
  5. Strategy fan-out — resolve_strategy_cycles(timeframe, strategies) yields (strategy, timeframe) pairs (swing / scalp / both). With more than one pair they run in a ThreadPoolExecutor with one worker per strategy; with one pair they run inline (~4453–4464).
  6. Per-strategy isolation — each worker calls orch.execute_cycle(...) inside try/except; a cycle error is logged and the loop continues on the next pulse. KeyboardInterrupt is re-raised so an operator can always stop the process (~4410–4444).
  7. Reconnect — client.reconnect_if_needed() keeps a dead MT5 session from poisoning the next pulse (~4371).
  8. Pipeline selection — PIPELINE_V2 defaults to on; when enabled the loop calls orch.execute_cycle_v2 (installed by core/harness/pipeline_v2.install_orchestrator_entrypoint()), otherwise the legacy execute_cycle (~4378–4415). --no-pipeline-v2 or PIPELINE_V2=0 forces legacy.
  9. Circuit evaluation — _cb_autonomy().evaluate_circuits(_risk_snapshot) re-evaluates halt / pause / demote conditions from the live risk snapshot each pulse (~4647).
  10. Cadence — the loop waits --poll-interval seconds (default 5) between pulses and refreshes dashboard footer/log state.
Cadence doctrine. The pulse is not the decision rate. Most pulses end in the maintenance prefix plus an early HOLD because no new completed candle exists for that strategy (_completed_candle_candidate ~2956). Decision rate is driven by candle closes and events; pulse rate drives reconciliation, protective management and telemetry.

04.3 What a HOLD actually does (and does not do)

It does

  • Journal the reason with symbol/strategy/timeframe context through operations events and the proposals table.
  • Complete or fail the leased task so the same candle is not retried forever (complete_task / fail_task at ~5838, ~5859, ~6755, ~6763, ~6975).
  • Emit a bus/telemetry event so the deck can display why nothing traded.
  • Leave the completed-candle lease in a state that lets the next pulse re-evaluate.

It never does

  • Place, modify or cancel an order.
  • Write a trade row (trades) — only executed fills create trades.
  • Mutate risk parameters.
  • Silently swallow provider budget: the attempt records success/failure so RESERVED budget cannot stick until lease expiry.
