13 13. Orchestration Internals: State Assembly, Arbitration & Debate

13.1 The state payload ("TOON")

The decision payload is a plain-dict state tensor serialised for the model. It is assembled incrementally through the cycle (§04.2 stages 10–14) and then hardened before the call:

  • _round_floats(obj, precision=5) (~1075) bounds float precision recursively so the payload is stable and diffable.
  • _sanitize_toon_lite_budget(toon_lite, max_total_chars=60000) (~1088) drops/compacts the most expensive blocks when the payload exceeds budget, rather than letting the provider reject it.
  • _format_lessons_learned() (~1032) and _get_knowledge_base_context(toon) (~1044) inject retrieved memory (§12) as bounded text.

13.3 Signal arbitration

intelligence/signal_arbitrator.py reduces several candidate signals to one scored view: _extract_signals_from_state(state) (~170) pulls signals from the state; _direction_agrees(signal_dir, regime_bias) (~68) scores regime alignment; _causal_support(signal_side, causal_paths) (~129) scores macro-path support; _event_alignment(event_state) (~154) scores event alignment; _narrative_decay_state(decisions) (~54) recognises a thesis that has already decayed; _score_signal(...) (~292) and arbitrate_signals(...) (~344) produce the final pick.

13.4 Debate protocol

intelligence/debate_protocol.py implements an explicit bull/bear exchange: DebateTurn (~85) and DebateVerdict (~101) are the serialisable shapes; ApexQuantParliament.conduct_debate(...) (~165, ~182) dispatches to _conduct_deterministic_debate(...) (~221) — the reproducible default — or _conduct_llm_debate(...) (~446) when a model is available; and as_veto_caller() (~493) exposes the result to the permission path as a veto function.

13.5 The universal decision engine (advisory)

intelligence/universal_decision_engine.py evaluates a decision against explicit criteria, each producing a PhilosophicalAssessment (~69) inside a UniversalDecision (~81) and a DecisionVerdict enum (~56): _assess_epistemic_humility (~149), _assess_expected_value (~196), _assess_minimax_regret (~257), _assess_catastrophic_tail (~309), _assess_second_order (~360), _assess_via_negativa (~408), _assess_compensated_risk (~444), _assess_reversibility (~507). It is advisory: its verdict informs operators and the model, but the gates in §05 remain the only authority.

13.6 Pipeline V2: observability without behaviour change

core/harness/pipeline_v2.py re-expresses the cycle as declared StageSpecs. The maintenance prefix is already a real set of stages — velocity.poll, reconcile.pending, reconcile.open, memory.dispatch, position.tick, worker.heartbeat (lines 228–244) — followed by envelope stages (blackout gate ~158, portfolio consult ~170, legacy cycle body ~188). Because the extracted legacy body would otherwise repeat the maintenance work, request_skip_maintenance() / consume_skip_maintenance() (~41–45) hand over a skip token so both paths perform identical work, with per-stage duration and status emitted as span telemetry.
