22.1 The FastAPI server

gui/gui_api.py creates the app at line 82 (app = FastAPI()) and serves both a REST surface and a websocket. The trading process is the producer: it mirrors state into the server through POST /api/internal/update (via ui/web_dashboard_adapter.py), so the API is a read-model of the journal rather than a second source of truth.

Fail-closed surfaces. Endpoints backed by an engine expose an explicit offline state (for example the scanner returning ENGINE_OFFLINE) instead of an empty list that would read as "nothing to trade". This is the API-side expression of the same doctrine as the trading loop.

22.2 The OpenTUI command deck

tui_opentui/ is the single canonical interactive terminal: React/TypeScript on Bun, launched by python mt5_trader.py deck, START_DECK.bat, or automatically when the CLI is run bare (mt5_trader.py ~1263). Two transport modes are supported via TRANSPORT:

  • TRANSPORT=mcp — the deck spawns the MT5 MCP server (MT5_MCP_COMMAND=python, MT5_MCP_ARGS=-m metatrader5_mcp.main, configured in .env/.env.example and opencode.json).
  • TRANSPORT=live — talks to the API server, optionally auto-starting the MCP sidecar via MT5_MCP_AUTOSTART=1.

The deck's screens (pipeline, tasks, scanner, strategies, memory, compliance, settings) read the §22.1 API; the repository history records the deliberate removal of mock data from these screens, and every screen now surfaces the journal or an explicit offline state. Settings → Accounts accepts masked credentials and routes them to /api/config/accounts/secure.
