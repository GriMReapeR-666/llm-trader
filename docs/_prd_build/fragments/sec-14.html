14 14. Post-Trade Reflection & Continuous Learning

Everything here runs after a trade closes, on the slow lane, with no authority over positions. Its purpose is to convert outcomes into beliefs that are auditable, reviewable and — where they touch policy — gated.

14.1 The reflection graph

intelligence/reflection_graph.py is a LangGraph pipeline whose docstring states the contract: "Slow-Lane Post-Trade Memory Reflection & Consolidation Graph. Asynchronously processes closed trades, distills L1 Atomic Facts, updates L2 Scenario Documents, and recalibrates causal edge weights." It is checkpointed with SqliteCheckpointSaver (intelligence/graph_checkpointer.py), so a crash mid-reflection resumes rather than restarts.

14.2 Labels: the bridge from outcome to memory

TradingMemory.label_closed_trade(ticket, pnl, risk_amount, exit_reason) (intelligence/trading_memory.py ~1498) converts a close into a labelled outcome, and _setup_outcome_label(state, reason) (~1526) maps lifecycle states to labels. These labels feed scenario rebuilding (~759, explicitly including rejected and unresolved setups, so near-misses teach the system too), core-memory proposals (~961, review-gated) and retrieval-outcome resolution (~1346).

14.3 Reward attribution and the RL eligibility gate

Reward accounting lives in operations/reward_ledger.py and operations/reward_attribution.py, with sustainability checks in operations/reward_sustainability.py. Model updates are not automatic:

GateAnchorMeaning
_rl_learning_allowed()intelligence/llm_orchestrator.py ~3671Whether any RL update may be applied right now
_research_influence_allowed(model_kind, paper_mode=…)~3695Whether research output may influence this parameter set in this mode; paper is scoped separately from live
Research-influence ledgeroperations/research_influence_gate.pyWhich model kinds an operator has approved, revocable through the journal CLI

The same gate protects risk mutation elsewhere: a meta-adaptive engine may suggest a new risk_per_trade, but the write only happens when influence is approved; otherwise the suggestion is journaled and nothing changes.

14.4 Why reflection runs on its own lane

Memory work is submitted through DualVelocityExecutor.submit_slow(key, fn, limit=3) (operations/dual_velocity.py ~44–110) from the maintenance prefix, keyed memory:YYYYMMDDHH so the hourly batch deduplicates. A saturated slow lane returns {"status": "BACKPRESSURE"}, which raises a slow_lane_backpressure event instead of blocking the five-second market pulse. Fast-lane work (quotes, indicators, validation) is never queued behind a slow LLM call.
