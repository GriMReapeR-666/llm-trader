16 16. Research Validation Gates

Everything here is advisory input to sizing and validation. No gate can place an order; each can only veto or shrink. Their real power: their verdicts are read by the deterministic path in §05.4–05.5, so they change live behaviour without the LLM's consent.

16.1 Walk-forward and decay

core/walk_forward_validator.py with its real defaults:

constants (:78-83) DEFAULT_IC_WINDOW = 20 # rolling window for IC DEFAULT_IC_DECAY_THRESHOLD = 0.02 # IC below this = decaying DEFAULT_IC_CONFIRM_BARS = 3 # bars of decay before confirmation DEFAULT_HALF_LIFE_MAX = 100 # max half-life in bars DEFAULT_WFE_ACCEPT_THRESHOLD = 0.5 # WFE = OOS Sharpe / IS Sharpe STATE_FILE = "walk_forward_state.json" types & API DecayStatus (:90) · ICPoint (:98) · DecayReport (:113) · WalkForwardResult (:144) · WFEVerdict (:171) detect_decay(:347) · _estimate_half_life(:475) · walk_forward_splits(:517) walk_forward_efficiency_gate(:583) · get_status(:629)

Consumption: walk_forward_status == "DEAD" zeroes size ("alpha is harmful, all entries blocked"), "DECAYING" halves it, and WFE < 0.5 scales size to max(0.5, WFE) while OOS Sharpe ≤ 0 zeroes it (core/risk_manager.py ~1066–1101). The validator refuses outright when WFE is below its floor (core/trading_safety.py ~1089–1103).

16.2 CPCV and the probability of backtest overfitting

core/cpcv_validation.py exposes CombinatorialPurgedCrossValidator.split(...) (~33) — combinatorial splits with purging/embargo so train and test cannot share information through overlapping labels — and calculate_probability_of_backtest_overfitting(...) (~102), the PBO estimate used to ask whether a good configuration is merely the luckiest of many. The same machinery is reachable from core/cpcv_backtester.run_combinatorial_purged_backtest and runs in the weekly research schedule (_execute_weekly_research ~5420).

16.3 The overfit detector and the overfit gate

core/overfit_detector.py returns four result types — OverfitResult (~40), DivergenceResult (~52), MinBacktestResult (~64), StepwiseFitResult (~76): an overall score plus targeted evidence (IS/OOS divergence, minimum-backtest robustness, stepwise selection).

core/overfit_gate.py BLOCKED_RISK_LEVELS = frozenset({"HIGH", "CRITICAL"}) # :34 validate_strategy(...) → GateResult # :92 check_strategy(strategy) → GateResult # :270 get_passed/rejected_strategies() # :362 / :355 state: overfit_gate_state.json (per strategy)

Downstream: CRITICAL → size 0, HIGH → ×0.25 (core/risk_manager.py ~1103–1114); the validator vetoes with "overfit gate REJECT: risk=…".

16.4 The trial ledger: paying for the number of attempts

core/trial_ledger.py records every experiment (TrialRecord ~46) and computes deflated statistics (DSRResult ~74) from n_trials() (~218) and trial_sharpes() (~225). The deflated Sharpe ratio answers the only question that matters after a hundred parameter tweaks: given how many things I tried, is this Sharpe surprising? Because the ledger is durable, attempts cannot be quietly forgotten — which is what keeps core/bayesian_update.py and promotion honest.

The consumption pattern is the point. Gate verdicts travel to the live path as toon["walk_forward_status"], toon["overfit_risk_level"], toon["data_drift_status"] and toon["walk_forward_wfe"]. The LLM sees them as context; the gates act on them as law. If a researcher disagrees with a verdict, the correct response is to change the gate's evidence — not to talk the validator out of it.
