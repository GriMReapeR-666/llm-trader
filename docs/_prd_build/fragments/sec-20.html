This section answers the question an operator actually asks: what happens when nobody is watching?

20.1 The supervisor kernel

operations/supervisor.py owns phases and liveness: phase() (~96), transition(target, reason) (~100), boot_sequence(checks) (~115), ready() (~139), note_component(name, ok, detail) (~147), heartbeat() (~152), note_principal(name, ok, detail) (~157) with stale_principals() (~170) and principal_freshness() (~185), plus degrade()/recover() (~197/~204), pause(), request_shutdown()/complete_shutdown() (~216/~220) and overall_health() (~227). The cycle notes principals explicitly — MarketModel when a decision is proposed, RiskController when validation passes or fails (intelligence/llm_orchestrator.py ~7140–7151) — so "silence" stays distinguishable from "refusal".

trading_allowed() is consulted at the top of every cycle, and the queue is drained at the same point, so a pause issued seconds earlier is honoured immediately; each drained record emits CONTROL_EXECUTED.

ActionEffectLine

20.5 Guardians, watchdog and recovery

  • Ψ External Guardian (core/external_guardian.py) — out of process, polls the broker directly, hardcoded thresholds, 120 s heartbeat watchdog; started after bootstrap so startup time is not mistaken for a hang (mt5_trader.py ~4207).
  • Live execution safety supervisor (core/execution_safety_supervisor.py): record_heartbeat (~62), update_equity (~66), validate_pre_trade_safety (~114), trip_circuit_breaker (~153) and reset_circuit_breaker(authorization_token) (~160) — clearing a breaker requires an explicit token, so it cannot be reset by accident.
  • Degradation and health: operations/degradation_detector.py, operations/health_alerts.py, operations/system_doctor.py, core/crash_detector.py.
  • Crash / restart recovery: core/crash_recovery.py (startup_recovery(), hash-chained checkpoints, atexit/SIGTERM hooks) and operations/restart_recovery.py.
  • Kill switch: data/kill_switch_latch.py plus the validator's kill switch active rule (§05.4) and the flatten/killswitch control actions.

20.6 One unattended day (paper mode)

00:00 process starts → boot gates → bootstrap → loop begins every 5 s pulse: autonomy gate · maintenance prefix · schedules · candle lease? new completed bar → ingest → quality → news → features → LLM → gates every 10th autonomous research tick (discovery / registration / lifecycle) hourly slow-lane memory distillation (limit 3) → L1 facts, narratives session end _execute_session_review daily _execute_daily_review → daily narrative, reconciliation, labels weekly _execute_weekly_research → weekly narrative, core consolidation, CPCV/WF monthly memory maintenance + archive of stale candidates continuous circuits evaluated every pulse; demote / pause / halt as needed on holiday no analysis; maintenance, health and kill-switch continue
What "perfect autonomy" means here. The process never dies on a transient LLM or MT5 fault; every HOLD and rejection is journaled; maintenance runs without a new candle; schedules actually execute and write their last_* state; the factory may demote but never self-approve live; and the deck shows the same journal the loop writes.
