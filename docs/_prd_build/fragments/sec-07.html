07 07. Data Ingestion & Source Fabric

Every number the system later reasons about enters through one of exactly four ingestion planes: the MT5 terminal plane (ticks, OHLC, depth-of-market, account), the HTTP/REST provider plane (NewsAPI, FRED, SEC EDGAR, Yahoo Finance, OpenBB, Seeking Alpha, Portfolio123, EIA, CFTC, Exness, Forex Factory), the RSS plane, and the calendar plane (broker calendar DLL → wrapper → structured event rows). This section documents how each plane is reached, what is cached, what is written to disk, how providers are circuit-broken, and exactly which failures are permitted to reach a trading decision.

07.1 Doctrine: no synthetic fallback, no unattributed data

The governing rule is enforced at the lowest level of the stack and restated at every layer: market data is either authenticated broker data, or the cycle does not happen. There is no "synthetic candle" path anywhere in data/market_data_provider.py.

07.2 The MT5 terminal plane

All terminal access is funnelled through three indirection helpers so a running mt5_trader.py session can inject its own initialised module instead of letting each module import MetaTrader5 independently (data/market_data_provider.py:78-97):

_get_mt5()        -> sys.modules["mt5_trader"].mt5   or module-level mt5
_get_fetch_ohlc() -> sys.modules["mt5_trader"].fetch_ohlc (unless it is this very function)
_get_tf_const()   -> sys.modules["mt5_trader"].tf_const   (unless it is this very function)

Timeframes map by name in TIMEFRAME_MAP (M1…MN1) and resolve via getattr(mt5_inst, "TIMEFRAME_" + tf), raising ValueError(f"Unsupported timeframe {tf}") on an unknown label (data/market_data_provider.py:99-117).

07.2.1 OHLC retrieval

fetch_ohlc(symbol, timeframe, count=100) (data/market_data_provider.py:183-243) performs, in order: terminal probe → symbol_info lookup → symbol_select(symbol, True) when present but not visible → copy_rates_from_pos(symbol, tf, 0, count) → DataFrame → server-timezone correction → set_index('time').

07.2.2 Broker server-time decoding (the look-ahead trap)

MT5 bar epochs are in the broker server's timezone (MetaQuotes demo servers run UTC+3), not UTC. Decoding naively makes every completed bar appear hours in the future, so the feature-lineage validator rejects every proposal as look-ahead. _server_utc_offset_seconds() (data/market_data_provider.py:127-180) probes symbol_info_tick() on EURUSD/GBPUSD/XAUUSD, snaps the residual to a 30-minute grid (clamped to ±14 h), discards probes with residual > 300 s (frozen/stale tick), takes the modal offset, and requires either 2+ agreeing votes or a single vote with residual ≤ 120 s. The result is cached 24 h (_SERVER_OFFSET_TTL = 24*3600, data/market_data_provider.py:120-124) so weekend-closed markets keep the last known offset. Returning 0 means "no trustworthy probe" — the code then deliberately keeps the naive decode rather than guessing wrong.

07.2.3 Timestamp-preserving serialisation

ohlc_records(df) exists because DataFrame.to_dict(orient="records") silently drops the index, which stripped every bar of its time and made the validator reject every proposal with "completed bar timestamp is missing or malformed". The helper resets the index, formats it to %Y-%m-%dT%H:%M:%SZ, and renames the column to time (data/market_data_provider.py:246-267).

07.2.4 Depth of market

DOMCollector wraps market_book_add / market_book_get / market_book_release (data/market_data_provider.py:356-406). Snapshot fields: captured_at, source="mt5_dom", available, best_bid, best_ask, spread, bid_vol_total, ask_vol_total, imbalance, dom_depth = min(len(bids), len(asks)), top_bids[0:5], top_asks[0:5]. Unsubscribed or empty books return available: False with no prices — it never fabricates depth.

Subscription is short-lived and polled, not slept: fetch_data retries get_snapshot() up to 5 times with 200 ms gaps (1 s ceiling) instead of a blind sleep(1), then unsubscribes (data/market_data_provider.py:1172-1181).

07.3.2 Exponential backoff and key rotation

Per-service backoff state starts at {"last_429": 0.0, "delay_sec": 10.0} for newsapi, fred and seeking_alpha (data/api_manager.py:71-75). A 429/quota error calls record_rate_limit(), which doubles delay_sec up to a 300 s ceiling (data/api_manager.py:227-234); is_service_backed_off() suppresses further calls until the window elapses (data/api_manager.py:220-225). rotate_key() advances the pool index, rebuilds the client, and resets that service's backoff window to 10 s (data/api_manager.py:236-250). On error paths the caller inspects the error string for "429", "rate" or "too many" before rotating (data/api_manager.py:320-323 for news, :442-444 for FRED).

07.3.3 Response shapes

  • get_news(keywords, language, page_size) → list of {source, title, description, url, published_at, sentiment} where sentiment comes from the local lexical estimator _estimate_sentiment() (data/api_manager.py:265-323, 374-392).
  • get_fred_data(series_ids) → per-series {value, date, previous, surprise} where surprise = latest - previous (data/api_manager.py:393-455).
  • get_sec_filings(ticker, filing_types=["8-K","10-Q"]) → CIK-resolved EDGAR rows; an unresolved ticker returns [] with a warning (data/api_manager.py:457-516).
  • get_status() → the operator-visible source table: OpenBB, Portfolio123 and Seeking Alpha are reported ONLINE/DEGRADED/OFFLINE; Seeking Alpha is DEGRADED when instantiated but is_live is false with a _last_error (data/api_manager.py:550-575).

07.4 The calendar plane

Calendar access is a three-step cascade. Only steps 1 and 2 produce a source label that the deterministic gates accept; a Forex Factory row is an advisory source and the code says so.

  1. Configured enhanced calendar. MarketDataProvider.__init__ locates terminal64.dll under terminal_info().path (falling back to MQL5/Libraries/terminal64.dll) and calls create_enhanced_calendar_wrapper(dll_path=...); on any failure self.calendar = None with the comment "Enhanced calendar unavailable; no calendar fallback is trusted" (data/market_data_provider.py:721-739).
  2. MT5 native calendar. collect_calendar_event_rows() first asks the wrapper for get_events(limit=5, min_importance=2, currencies=["USD","EUR","GBP","JPY"]), labelling the source configured_calendar (or ERROR if it raises). If that yields nothing it calls mt5.calendar_get(naive_anchor, naive_anchor + 24h), keeps events with importance >= 2, sorts by time, takes the first five, and labels the source mt5_calendar. Each row is normalised to {time, currency, event, importance, forecast, previous} (data/market_data_provider.py:270-325).
  3. Forex Factory fallback. collect_calendar_event_rows_with_ff() calls ForexFactoryProvider().fetch_calendar(min_impact="HIGH"), takes at most five events, promotes impact=="HIGH" to importance=3 and everything else to 2, and sets source="forex_factory" (data/market_data_provider.py:328-353). The provider reads https://nfs.faireconomy.media/ff_calendar_thisweek.json with an 8 s timeout and a cache at artifacts/forexfactory_calendar_cache.json, mapping colour codes RED/ORANGE/YELLOW/GRAY onto HIGH/MEDIUM/LOW/HOLIDAY and deriving datetime_utc = f"{date}T{time}Z" (data/forexfactory_provider.py:18-19, 96-147, 158-190).

Consumers gate on the label, not on the object. The orchestrator computes calendar_ready = calendar_source in {"configured_calendar", "mt5_calendar"} and passes that boolean into per-setup data requirements. A "forex_factory" or "UNAVAILABLE" source therefore fails closed for every setup whose requirements demand a calendar (intelligence/llm_orchestrator.py:2495-2505).
