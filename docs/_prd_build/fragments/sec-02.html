02 02. Architecture Doctrine, Agent Graph & Layer Map

02.1 The formal model: Γdeployed = (Γ, Ψ)

The system is specified as a graph plus an out-of-process guardian:

Γ_deployed = ( Γ , Ψ ) Γ = ( A , E , S , Φ , Θ , T ) # the trading graph A = autonomous agents (stateless stages) E = relational edges (data / permission / feedback) S = authoritative state tensor (SQLite journal + keyed state store + JSON) Φ = state-transformation functions (deterministic; replayable) Θ = orchestrator scheduling priority T = trigger mechanisms (candle close, event, schedule, circuit) Ψ = External Guardian — out-of-process, fail-closed kill authority independent of Γ so that a defect inside Γ cannot silence it

Two implementation facts make this concrete rather than aspirational:

  • Ψ is a separate process. start_guardian() is launched after bootstrap and before the pulse loop, only when the run is not paper mode — see mt5_trader.py ~4207–4216. Its thresholds are hardcoded in core/external_guardian.py, not read from the LLM's configuration.
  • Φ is deterministic and LLM-free. Everything in core/ that validates, sizes, arbitrates, routes or sizes an order can be replayed without an API key — which is why the test suite can assert on it.

02.3 The three graphs

Trade Graph (authoritative)

The real path: mt5_trader.py pulse loop → LLMOrchestrator.execute_cycle → gates → order. This is where authority lives and where the journal is written.

Deliberative Graph (shadow)

A LangGraph pipeline that runs an observation-only copy of the reasoning chain each pulse. It writes observations, never orders.

Reflection Graph (post-trade)

Runs on closure: equity state update → coach → scenario consolidation → macro feedback. It updates beliefs, not positions.

Deliberative Graph node sequence

STARTtrigger→ technical_netfeatures / structure→ macro_analystmacro + Laya BERT→ memory_retrieverL0–L3 recall→ market_modelLLM router→ signal_arbitratoragreement→ debate_protocolbull vs bear→ risk_controllergate→ order_executionor rejection_sinkcodes→ END

Declared in intelligence/deliberative_graph.py lines 65–95: nine nodes, a linear chain from technical_net to risk_controller, then a branch to either order_execution or rejection_sink. Node implementations live in intelligence/graph_nodes.py (TechnicalNetNode 65, MacroAnalystNode 129, MemoryRetrieverNode 534, MarketModelNode 568, SignalArbitratorNode 683, DebateProtocolNode 773, RiskControllerNode 887, OrderExecutionNode 1105, RejectionSinkNode 1172, QuantitativeCoachNode 1247).

How the shadow graph is invoked. In the pulse loop the orchestrator invokes the compiled graph with create_initial_trading_cycle_state(...) and discards the result — the comment in mt5_trader.py ~4466 states it plainly: "Deliberative Graph shadow cycle (observations only)". This keeps the graph executable and instrumented without granting it authority.
