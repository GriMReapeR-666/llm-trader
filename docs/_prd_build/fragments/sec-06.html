06.2 Paper-broker safety rules (all fail-closed)

  • pending_order accepts only buy_limit, sell_limit, buy_stop, sell_stop; anything else → 10013 invalid paper pending order type.
  • Expired pending orders are rejected (paper pending order is already expired).
  • close_position requires a matching non-zero magic (paper position identity/magic ownership mismatch otherwise) and refuses to close more than the position holds.
  • History is trimmed at 2000 entries (keeps the newest 1000) so a long paper run cannot exhaust memory.

06.3 The live submit path, step by step

  1. Parameter validation — validate_order_params(side, price, sl, tp, atr) (~192).
  2. Pending geometry — validate_pending_entry_geometry(otype, entry, bid, ask) (~224), reordering a limit that would already be marketable.
  3. Distributed lock — an order:<symbol> lock is acquired before submit; failure returns {"error": "lock_timeout"} instead of racing (~309–318). This is what makes the parallel strategy pool safe.
  4. Dynamic deviation — calculate_dynamic_slippage_deviation (~247): urgency ≥ 0.70 → deviation ≈ 1.5 × spread (accept slippage to avoid requotes); urgency ≤ 0.30 → 0.8 × spread (protect against slippage); otherwise 1.0 ×. Clamped to [5, 150] points; falls back to a 20-point base when the spread is unknown.
  5. Filling mode — _broker_market_filling_mode(symbol) reads the broker's allowed filling modes instead of assuming one.
  6. κ audit — the result is written to the hash-chained compliance log as EventType.ORDER_FILLED or EventType.ORDER_REJECTED with retcode, ticket, SL/TP (~344–358).
  7. Non-DONE retcode — raises RuntimeError("Market order failed: retcode=…"), releasing the lock; the cycle journals the rejection. There is no retry-on-reject loop that could double-fill.
  8. Post-execution advisory — UrgencySmartOrderRouter recomputes urgency from spread, order-flow imbalance and depth and returns an execution_routing advisory that is logged for telemetry (not a second order) (~367–386).

06.4 Broker contract and execution policy

Before any live order, the system needs a verified contract description. core/broker_preflight.py captures symbol and account specs (SYMBOL_FIELDS ~16, ACCOUNT_FIELDS ~24, required fields including login, server, currency, leverage, trade_allowed, trade_expert), fingerprints them (fingerprint ~59) and compares against the stored one (has_contract_changed ~64). A changed contract invalidates the stored execution policy.

core/execution_policy.py stores a per-symbol, per-broker-fingerprint policy that must validate against REQUIRED fields (~15: version, symbol, broker_fingerprint, max_spread_price, …) and must be approved by an operator (approve_for_store ~162). An unapproved policy means no order for that symbol — by design.

The R basis is captured once per ticket by _initial_risk_for (~402) from the initial stop, before any breakeven or trailing move mutates it — otherwise trailing would shrink the R reference each tick. If the initial stop is missing it falls back to ATR.

Every management action is authorized, not assumed. _authorize_management_action (~269) is called before each close/modify; a refusal is logged as PARTIAL_CLOSE_REJECTED or Protective flatten refused and the manager moves on. Unowned positions (foreign magic) are recorded in manual_activity as UNOWNED_POSITION_OBSERVED with action observe_only — the system never touches a position it cannot prove it owns.

06.6 Post-fill and close reconciliation

After any fill or close the orchestrator records broker execution reports (fill price, slippage, spread at submit and fill, implementation shortfall, requote count, execution latency — columns added by migration in core/trading_safety.py ~284–290), position observations with mark_quality, and lifecycle events. reconcile_pending_orders, reconcile_open_positions and reconcile_daily_broker_history (intelligence/llm_orchestrator.py ~4766, ~4538, ~4734) compare broker truth against the journal during every maintenance prefix, so a restart or a dropped connection cannot leave the system believing in a position the broker no longer holds.
