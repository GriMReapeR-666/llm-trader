docs/_prd_build/ shell_head.html # doctype, CSS, sidebar chrome shell_foot.html # footer + TOC behaviour fragments/sec-01.html … sec-27.html scripts/build_prd_doc.py # stitcher + validator (--check) workflow edit fragment → python scripts/build_prd_doc.py --check → build output docs/SYSTEM_SOURCE_OF_TRUTH_PRD.html # single self-contained file, no external assets

The validator enforces the conventions this document relies on: exactly one <section> per file, an <h2 id> heading, balanced table/div/details/pre markup, and the absence of <html>/<script>/<h1> inside fragments. Sections 01–27 are all required, so deleting one fails the build rather than silently shrinking the manual.

Final reminder. Where this document and the code disagree, the code is authoritative — and the disagreement itself is a documentation defect worth fixing with the same care as a trading defect, because the next operator will read this file.
